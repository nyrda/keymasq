# Keymasq agent reference: macros

Use this file for `keymasq` macro commands and macro JSON.

Macros are stored in daemon-owned files:

```text
/var/lib/keymasq/macros/*.kmacro.xz
```

Do not edit those files directly. Use the GUI or CLI.

The key selector's Type tab creates normal stored type macros with generated
`type_text_*` names and maps them in one step. These macros appear in normal
macro lists and the Macro Library.

## CLI commands

```bash
keymasq macros list
keymasq macros create <name> [--force] [JSON]
keymasq macros play <name> [--speed SPEED]
keymasq macros delete <name>
keymasq macros cancel
```

`macros create` accepts either a macro object with `events` or a raw event
list. The CLI-provided name is always used as the stored macro name. It reads
JSON from stdin when no JSON argument is provided. Created macros use the
normal timeline model and can be opened in the GUI editor.

## Built-in compiler

Prefer the `keymasq type` compiler over hand-written event JSON when possible.

```bash
# type text immediately
keymasq type "hello<tab><wait:20>world"

# print JSON for a type macro
keymasq type "hello<enter>" --print-json

# create a stored type macro
keymasq type "hello<enter>" --print-json \
  | keymasq macros create say_hello --force
```

## Macro JSON

Canonical macro object:

```json
{
  "name": "example",
  "device_types": ["keyboard"],
  "duration_us": 20000,
  "loop_mode": "none",
  "loop_count": 1,
  "loop_stop_behavior": "finish_run",
  "block_mouse_movement": false,
  "events": [
    {"device_type": "keyboard", "type": 1, "code": 30, "value": 1, "t_us": 0},
    {"device_type": "keyboard", "type": 1, "code": 30, "value": 0, "t_us": 10000}
  ]
}
```

Raw key/button event fields:

- `device_type`: `keyboard`, `mouse`, `gamepad`, or `macro`
- `type`: Linux evdev event type, usually `1` for key/button
- `code`: numeric Linux evdev code
- `value`: `1` down, `0` up, `2` repeat
- `t_us`: timeline timestamp in microseconds

Semantic macro control events:

```json
{"device_type":"keyboard","type":1,"code":30,"value":0,"t_us":0,"macro_action":"macro_rapidfire","duration_us":100000,"rapidfire_hold_ms":10,"rapidfire_wait_ms":10}
{"device_type":"macro","type":0,"code":0,"value":0,"t_us":0,"macro_action":"wait","duration_us":10000}
{"device_type":"macro","type":0,"code":0,"value":0,"t_us":0,"macro_action":"wait_random","min_us":10000,"max_us":50000}
{"device_type":"macro","type":0,"code":0,"value":0,"t_us":0,"macro_action":"mouse_move_abs","x":100,"y":200}
{"device_type":"macro","type":0,"code":0,"value":0,"t_us":0,"macro_action":"mouse_move_rel","x":10,"y":0}
{"device_type":"macro","type":0,"code":0,"value":0,"t_us":0,"macro_action":"mouse_move_natural_abs","x":100,"y":200,"speed":12000.0,"jitter":0.3,"curve":"natural","tolerance":2,"max_duration_ms":3000,"stop_on_failure":false}
{"device_type":"macro","type":0,"code":0,"value":0,"t_us":0,"macro_action":"exec_sync","command":"echo ready","timeout_ms":30000,"inhibit_mouse":false}
{"device_type":"macro","type":0,"code":0,"value":0,"t_us":0,"macro_action":"exec_parallel","command":"sleep 1","timeout_ms":30000,"inhibit_mouse":false}
{"device_type":"macro","type":0,"code":0,"value":0,"t_us":0,"macro_action":"exec_async","command":"notify-send done"}
{"device_type":"macro","type":0,"code":0,"value":0,"t_us":0,"macro_action":"macro_sync","macro_name":"child","loop_mode":"none","loop_count":1,"loop_stop_behavior":"finish_run","speed":1.0,"replay_mouse_movement":true,"replay_mouse_clicks":true}
{"device_type":"macro","type":0,"code":0,"value":0,"t_us":0,"macro_action":"macro_parallel","macro_name":"child","loop_mode":"hold","loop_count":1,"loop_stop_behavior":"cancel_run","speed":1.0,"replay_mouse_movement":true,"replay_mouse_clicks":true}
```

macro_rapidfire pulses a keyboard, mouse, or gamepad button for duration_us.
Use type=1 and the target code; gamepads can specify output_id. Set
rapidfire_hold_ms and rapidfire_wait_ms. Gaps adjust so
the final release lands at the block's end.

loop_stop_behavior also accepts "pause_run" for none/count/hold playback and
child calls. Release cleans up this instance's held outputs and freezes its
timeline; pressing the same trigger resumes without restarting. Later releases
already emitted by cleanup are skipped. Active waits count real time while
paused; commands and natural mouse moves finish normally. Child calls inherit
trigger state, not the parent's release policy. A press resumes all paused
invocations of that mapping instead of starting another root. Parallel children
remain joined at the end of the parent pass. Without a trigger, pause is ignored.

pause_timeout_s is the maximum paused duration in real seconds since trigger
release; 0 or omitted means Never. Resume clears the timer; each later release
starts a new one. Each pause-enabled child call can supply its own timeout.
Expiry cancels that instance and its descendants, including their active mouse
moves and waitable commands. Parents and siblings keep their own policies: a
paused parent stays paused, while an ordinary synchronous parent can continue
after the expired call. Never does not prevent cancellation by an ancestor.
After a top-level expiry, the next press starts fresh. Newly enabled pause in
the GUI defaults to 60 seconds; older saved
pause configurations retain Never. Profile TOML uses pause_timeout_s; internal
mapping payloads use macro_pause_timeout_s.

Recorded macro start positioning is represented as the first
`mouse_move_natural_abs` event at `t_us=0`, with `speed=100000.0`,
`jitter=0.0`, and `curve="linear"`.

Natural mouse move events block macro playback until movement finishes or times
out. Later event deadlines are shifted by the elapsed movement time. If
`stop_on_failure` is true and the move returns an error, the current macro run
stops before later events execute.

Loop modes for saved macros: `none`, `count`, `hold`, `toggle`.
`loop_stop_behavior` accepts `pause_run` for `none`, `count`, and `hold`,
including child calls. `finish_run` and `cancel_run` select the stop policy
for `hold` and `toggle`; `pause_run` is not supported for `toggle`.
For `none` and `count`, the default `finish_run` means continue on release.

Macro call events dynamically resolve `macro_name`. `macro_sync` blocks the
parent at the call site; `macro_parallel` continues the parent timeline but joins
the child before the parent iteration completes. Child `loop_mode` accepts
`none`, `count`, or `hold`; nested toggle is treated as `none`. Hold inherits
the root key lifecycle and is treated as one run when playback has no source.
Parallel children never detach from the parent. Child failures abort the call
tree and log the dynamic call chain. Before spawning a child, the runtime
rejects its name if that name already appears in the active parent chain. The
failure includes the attempted cycle and aborts the call tree. Keymasq does not
scan saved macros or impose a separate depth limit.

Exec modes: `exec_sync` waits at the event; `exec_parallel` continues the
timeline and joins before the parent iteration completes; `exec_async` is
detached and can outlive the macro. `exec_sync` and `exec_parallel` share the
same `timeout_ms` policy and optional `inhibit_mouse` behavior. Canceling a
joined command kills its session-owned process group.

## Binding a macro from a profile

Create or update the macro first, then reference it by name:

```toml
[devices."1234:5678".mapping.btn_extra]
action = "macro"
target = "double_click_10ms"
replay_mouse_movement = true
replay_mouse_clicks = true
speed = 1.0
loop_mode = "none"
```
